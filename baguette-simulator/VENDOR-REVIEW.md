# Vendored runtime evidence

Upstream: [tddworks/baguette v0.2.0](https://github.com/tddworks/baguette/releases/tag/v0.2.0), macOS arm64 release. Original release archive SHA-256: `8d382a4c9efe1e64ea591353bb10fec3bd46ec1ef909d63be1bee9c201f4ef3b` (downloaded from the official GitHub release and matched against its asset digest on 2026-09-26). The two native executables are rebuilt from the official source with the patch documented below; `vendor-inventory.json` enumerates all 97 packaged upstream files with SHA-256 and byte size. Official logo is resized to 512×512 within Cindy’s 512 KiB limit.

## Exact source modifications

`vendor-web.patch` is the complete diff against `Sources/Baguette/Resources/Web` at tag v0.2.0 (official release archive Web resources). These eleven Web files differ (nine carried-forward patches, the reviewed Duo edge-drag fix and the Chromium touch fix):

- `stream-session.js`: bounded reconnect after unexpected socket close; cancel scheduled reconnect on deliberate stop.
- `baguette/parts/keyboard.js`: delegate key/text/clipboard actions to the same-origin /clipboard private-device bridge (fragment port never selects a destination), suppress OS repeats and duplicate in-flight paste, serialize keys/paste/copy, report queue overflow with English fallback for added input errors, drop unsent keys on blur/hide/detach/release.
- `baguette/parts/bezel.js`, `baguette/carplay/carplay-frame.js`, `sim-native.html`: standard arrow cursor instead of crosshair.
- `baguette/gestures/touch-gesture-source.js`: when the browser has no Safari `gesture*` events (Chromium), a second finger streams the two real touch points as `touch2-down/move/up` (lifting any single touch first, ending on the first lift or cancel) instead of only painting the overlay; with `GestureEvent` present the original hand-off to `SafariGestureEventSource` is untouched, so no touch2 sequence is sent twice.
- `baguette/parts/keyboard.js` (additional to the bridge changes above): without `GestureEvent`, a hidden, pointer-events-none `<textarea inputmode="none">` (focusable and able to receive committed text, but no soft keyboard when a touch Chromium taps the screen) inside the screen element takes focus; `beforeinput` `insertText` and `compositionend` commits go through the existing `paste()` bridge and the sink is emptied. `pointerdown`/`touchstart` (capture, passive) on the screen element also move focus to the sink (and focus the viewer frame), because the touch source cancels `touchstart` and so no `mousedown` ever focuses the screen for touch input; this lets a host-side `insertText` land after a touch inside the embedded `iframe#screen` viewer. Key events from an active IME composition are ignored, `keydown` of the forwarded table and the document `paste` listener behave as before, and focus moving between the screen element and its sink is not treated as blur. Safari creates no sink and keeps its previous focus behaviour. Committed text goes through a new `commitText()` rather than `paste()`: the adjacent-duplicate suppression that guards a held Cmd+V had been dropping repeated characters typed one at a time (`hello` → `helo`), so commits are exempt from it. While a request is in flight, commits coalesce into the last queued commit (one exact string, order with queued keys preserved), and `_planCommit` decides delivery: printable US-keyboard ASCII and newline become one `type` request per run of up to 256 characters (HID key chords through the first-party helper, no pasteboard — a plain paste of `ello world` after `h` made the device insert a separating space, `h ello world`, and a lone-space pasteboard write was unreliable); everything else (CJK, emoji, accents) is pasted, and a multi-character paste that starts with a word character right after a word character the viewer delivered is sent one character at a time. Fresh fields, text after a tap, after a space or after punctuation, and CJK text stay a single request. The last delivered character is tracked in memory only (never the full text) and reset by pointer/touch input and by errors. `#cindyTextInput=paste` in the viewer URL fragment restores paste-only text. The last 50 round trips (action, character count, round-trip and server durations — never contents) are kept in `window.__baguetteInputTimings`.

- `farm/farm.html`: remove remote font/preconnect links; keep the existing system-font fallback and all Device Farm controls.
- `sim-location.js`: map tiles/search use same-origin `/map/` routes; the Node worker validates coordinates/query length and sends HTTPS only to fixed OSM hosts, with no redirects or forwarded credentials.
- `sim-native.js`: toolbar labels use textContent, preserving literal text instead of interpreting DOM-sourced titles as HTML.
- `sim-native.html` / `sim-native.js` (additional to the cursor and label changes above): a hidden `#cindyGear` button is the last child of the toolbar's `.tb-controls`. When the page is framed, it is shown, hidden and relabelled only by a `cindy-gear` `postMessage` whose origin is the viewer's own and whose source is the parent window; a click posts `cindy-gear-toggle` back to the same origin, and the viewer posts `cindy-gear-ready` once. Every change re-runs `layoutToolbar`, so the toolbar folds around the extra button. Standalone (not framed) it stays hidden. No network, storage or dynamic-execution change.
- `sim-3d.js`: fallback selector escaping uses CSS hexadecimal escapes for every code point, including backslashes and quotes.

The first-party `native/keyboard.m` adapts Baguette’s SimulatorKit ABI and device resolution (Apache-2.0); its source and `native/build.sh` accompany the ad-hoc signed Apple Silicon binary. It waits for every delivery completion, releases keys on partial failure, refuses a foreign/default device set and serializes helper access using a per-device lock. It does not restart SpringBoard or extract clipboard/account contents.

## Outbound-domain and execution scan

Source URL scan of all vendor JS/HTML/CSS/JSON identified:

- `nominatim.openstreetmap.org`, `tile.openstreetmap.org`: pre-existing optional location search and map tiles (`sim-location.js`). User-triggered functionality now routed through the autonomous Node worker fixed endpoints; browser requests stay same-origin.
- `fonts.googleapis.com`, `fonts.gstatic.com`: removed from `farm/farm.html`; existing CSS system-font fallbacks are used without font downloads.
- `leafletjs.com`: library attribution; `bugs.chromium.org`, `bugzilla.mozilla.org`: CSS comment references; `www.w3.org`: SVG namespace constant. These are not added runtime API clients.
- `127.0.0.1`: the added clipboard bridge; exact Origin and random capability required, request body capped at 40 KB, no clipboard content logging.

No eval/new Function calls or added executable base64 blobs were found in the ten modified upstream files or first-party Node/native code. Leaflet contains its upstream embedded transparent GIF and CSS assets; no executable payload was added. The full Baguette binary includes more upstream capabilities than the 16 exposed Agent tools: this PR does not claim to audit every native feature by reading JavaScript. Native binary and new plugin admission require maintainer review; the runtime’s own private-framework ABI is not a stable Apple API.

The plugin declares Node and loopback preview, uses fixed executable paths and argument arrays (never shell interpolation), no managed credentials, and launches Baguette with `--no-plugins`. Simulator apps retain their own network/auth state; App input may still trigger external actions. No command download occurs at runtime. Dependency licenses from the upstream tag’s Package.resolved (including build/test-only packages) and Leaflet 1.9.4 are reproduced in THIRD-PARTY-LICENSES.txt.

## Known limits and verification boundary

Native WebSocket disconnect SIGABRT was observed with 0.1.98; its status with 0.2.0 is not yet device-verified, so bounded recovery is preserved. Worker shutdown also stops the controller. Browser session ownership is separate from persistent simulator data. Historical tests cover the bridge and real iOS 27 native input. The installed 0.2.0 candidate checks are recorded below and in VERIFICATION.json.

The proxy bootstraps an HttpOnly SameSite=Strict capability cookie only from a token-authenticated control request. All proxied viewer HTTP, map and WebSocket routes require it; credentials are stripped before HTTP forwarding. The empty controller shell is public so its fragment can authenticate. This protects the proxy, not against same-user processes that can access CoreSimulator or the upstream Baguette loopback listener directly. Manual restart excludes only the retired child from crash accounting.

Minimum OS evidence: `xcrun vtool -show-build` reports `LC_BUILD_VERSION minos 15.0` for both bundled Baguette and native/keyboard. The worker checks `/usr/bin/sw_vers -productVersion` before launching either binary and rejects older or unrecognized versions with UNSUPPORTED_OS.

Viewer transport boundary: these scripts run in the external page opened by `cindy.preview`, not the plugin sandbox/Panel. Keyboard requests use relative `/clipboard` on that already-open preview origin; no hostname or port is chosen from input. `main.js` uses `cindy.node.request` to start the declared Node runtime and `cindy.preview` to open its declared preview host. The page has no `cindy.fetch` API. External OSM requests remain in fixed-endpoint Node code.

Native helper update: releaseKeys submits HID usages 4–231 before waiting once on a dispatch group, with a shared one-second acknowledgment deadline. Missing callbacks no longer prevent subsequent key-up submission. A serial callback queue aggregates delivery failures; timeout returns failure without reading mutable callback state, and late callbacks retain their resources. Rebuilt with `sh native/build.sh` and verified ad-hoc signature. Previous native/keyboard SHA-256 (single-chord helper): `96a8eeb56f41ab6bab253e96a2e85398f9d7009f8a50cf250dbfc48dc4c623fd`; the current helper's SHA-256 is recorded in the 0.1.24 section below. The macOS Objective-C regression compiles the production functions and uses actual dispatch queues, covering first/middle/last/all errors, no callbacks and delayed callbacks; it confirms all 228 submissions and a timeout under three seconds. This native regression is explicitly skipped on non-macOS runners. The keyboard helper binary is unchanged by the 0.2.0 upgrade; its Duo Unicode input was verified in the installed Cindy Beta package.

Scope: viewer Web only. No new network path, endpoint, credential, native code or dynamic execution: committed text uses the same-origin `/clipboard` bridge with the existing capability; touch2 frames use the existing WebSocket envelopes. `vendor-web.patch` and `vendor-inventory.json` are updated for `touch-gesture-source.js` and `keyboard.js` (inventory entries for the other 95 files are unchanged). No simulator was booted for this change. Real headless Chromium run (CDP) of the vendored modules against a mock screen/transport: one-finger then two-finger touch produced touch1-down/up then touch2-down, six touch2-move and touch2-up; `Input.insertText('中文ABC')` produced exactly one `beforeinput insertText` and one paste request, and a following real `a` keypress still produced one key request. Embedded layout (control page + same-origin `iframe#screen`, no prior focus): without the focus hand-off a CDP single-finger tap followed by `Input.insertText` reached nothing (no paste request, focus stayed on `BODY`); with it, the tap focuses the sink and `Input.insertText('hello 中文')` produced exactly one paste request. ### Typed text through the first-party keyboard helper (0.1.24)

`native/keyboard` now accepts a sequence of `(HID usage, modifier mask)` pairs (still exactly one pair for the old single-chord and release calls; at most 256 pairs, usage 0 only as the single release pair): one process loads CoreSimulator/SimulatorKit once, releases latched keys once, then delivers each chord (modifiers down, key down, 20 ms hold, key up, all modifiers up) and stops at the first failed chord, always attempting the release. `node/keys.cjs` adds `typeable`/`textChords`, mapping printable ASCII 0x20–0x7e and newline to the physical keys of a US keyboard (letters and digits, ` -=[]\\;',./` and their Shift partners), verified against an independent reference table for all 95 characters; `core.cjs` adds the `type` action (text of 1–256 characters, only typeable characters, otherwise `INVALID_ARGUMENT` before any process runs), and `clipboard.cjs` accepts it with the same capability/origin/device checks as `key`. No clipboard or pasteboard is touched for typed text, and the text never appears in process arguments (only usages). Rebuilt with `sh native/build.sh` (ad-hoc signed, `minos 15.0`); updated native/keyboard SHA-256: `8a12abdfe0ccdd7ffb931056068fefd5f2718c8e2791729a41b44a1303e216c9`. The native regression in `.tests/baguette/typed-keys.test.cjs` compiles `deliverChord` against a fake HID client and checks event order and the failure release.

Layout limit: the usages are physical keys, so the device's hardware-keyboard layout decides the resulting characters. The Simulator default is US; if a device was configured with another hardware layout, typed ASCII can come out wrong (for example swapped `y`/`z` on German) — use `#cindyTextInput=paste` in that case. Auto-correction and auto-capitalization of the focused field apply to typed characters as they would for a physical keyboard.

### Chromium two-finger touch: no phantom tap before the pair (`touch-gesture-source.js`, 0.1.27)

Found while chasing "pinch-out does nothing, pinch-in works" from the phone preview: the wire recordings show every pinch starting with `touch1-down`, `touch1-up` (a complete tap at the first finger) and only then `touch2-down`, because the first finger of any two-finger gesture landed alone and was sent at once. A tap right before the pair can fire whatever is under that finger and, when the fingers start close together (a pinch-out), it sits just before the pair like the first tap of a double-tap; a pinch-in starts far apart. That is a hypothesis about the iOS side, not something this change proves. In `vendor-web.patch` only the `touch-gesture-source.js` hunk changed (`vendor-inventory.json` updated for that file; no native change, no network or storage change): a lone finger is now held for up to 100 ms and sent as `touch1-down` when it moves, lifts or the window ends, so drags and taps start when they did and only a motionless press is delayed; a second finger inside the window sends `touch2-down` and nothing else; cancel or detach while held sends nothing. Applies to the Safari hand-off too (its first finger is no longer lifted because it was never sent). Checked with `node --test` against a recording mock screen and fake timers; on-device pinch-out is not verified.

### Lone-finger hold 100 -> 160 ms (`touch-gesture-source.js`, 0.1.28)

The E9 recordings of 8 pinches on 0.1.27 still began with `touch1-down`/`touch1-up` before `touch2-down` in 5 cases, all pinch-outs, `touch2-down` 0-15 ms after the up: the second finger reached the page 100-115 ms after the first, just past the 100 ms hold. Cause: the phone viewer sent the first finger's batch alone and the second finger waited for its acknowledgement (a round trip through the computer, 50-170 ms judging by the 50-170 ms spacing of the recorded moves). The viewer now sends both fingers together (Cindy side); the hold is raised to 160 ms so a slow ACK no longer lets the first finger through as a tap. Only the hold constant and its comment changed (`vendor-web.patch` hunk regenerated and applied to the upstream file to check it reproduces the vendored one; `vendor-inventory.json` updated for that file). A motionless press is delayed by up to 160 ms instead of 100 ms; a move, a lift or a second finger is not. Not verified on a device.

### Two-finger gesture never becomes a tap; nothing stays pressed (`touch-gesture-source.js`, 0.1.29)

E10 (phone preview, 0.1.28): of 5 pinches roughly 3 failed, and the wire recording of a failed one is `touch1-down` at the first finger's start position and `touch1-up` at its first moved position (about 9 px on), both in the same millisecond, no `touch2-*` at all; the simulator then showed a tap on whatever was under the finger and two translucent finger dots stayed on screen. Cause, reproduced in a real Electron webview with `Input.dispatchTouchEvent` against the vendored module: the handlers are bound to the screen element, a pinch that starts wider than the screen puts the second finger on the page around it, and a touch that lands on another element is never reported to this element (no `touchstart`, no `touchend`). The first finger's `touchmove`, whose `touches` lists every finger on the page, then arrived with two fingers while the source still held a single lone touch: it sent that touch (`touch1-down`), took the "late second finger after a streaming single touch" branch of the Safari hand-off (`touch1-up`, state `multi-deferred`) and waited for `gesture*` events Chromium never fires. The HUD dots painted for that state were cleared only by the normal `multi` end, so they stayed.

In `vendor-web.patch` only the `touch-gesture-source.js` hunk changed (`vendor-inventory.json` updated for that file; no native, network or storage change): (1) the finger count is also read from the document (capture, passive, no preventDefault) and from every `touchmove`, so a second finger outside the element starts the `touch2-*` pair at once and a held lone finger is dropped, never sent as a tap (Safari mode: left to `gesture*`, still no tap); a hold timer that fires while two fingers are down starts the pair instead of a press; (2) a lift while another finger is down elsewhere on the page is no tap; (3) when one finger of a streaming pair lifts, even one this element never heard of, the pair is released at once and the remaining finger does nothing; a third finger changes nothing; (4) everything pressed is lifted on touch cancel, on detach, when the page is hidden or closed (`visibilitychange`, `pagehide`) and when a new touch starts over a pair whose end never arrived; (5) the HUD dots are cleared on every way a gesture ends. A lone finger, a drag, an edge swipe and a tap behave as before. Checked with `node --test` against a recording mock screen and fake timers, and in a real Electron webview (CDP touch events) for the outside-finger pinch. Not verified on a device by this commit.
